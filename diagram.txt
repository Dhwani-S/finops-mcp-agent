 ┌──────────────────────────────────────────────────────────────────────────────────────────────────────────────┐
 │  SECURITY PRINCIPLES                                                                                        │
 │  ───────────────────                                                                                        │
 │  1. Sandboxed iframe (isolation for MCP App — no parent DOM, cookie, or storage access)                     │
 │  2. postMessage channel (ALL App ↔ Host communication — no direct agent bypass)                             │
 │  3. No Privilege Escalation (Host controls which tools/capabilities each App can access)                    │
 │  4. MCP Elicitation for auth gates (ctx.elicit — spec-compliant, NOT "out-of-band")                        │
 │  5. SQL guardrails (blocked DML/DDL keywords), bytes-billed caps, result truncation                        │
 │  6. Namespace-based access control on Context Lake (teams control public vs private visibility)             │
 │  *  3LO/PKCE and other auth concerns are layered on separate MCP extensions                                │
